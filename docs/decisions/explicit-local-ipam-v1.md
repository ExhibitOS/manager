# Explicit local IPAM v1

A network-capacity failure must not prune networks, modify daemon address pools or rewrite an already approved bundle. A caller may explicitly prepare a new bundle with a selected canonical /28 within 10.240.0.0/16, then independently approve its exact OED, manifest, Compose and executable hashes. OED v1 remains unchanged. The optional manifest field `explicitLocalNetwork` has exactly `mode: explicit-rfc1918-v1`, `subnet` and `gateway`. The gateway is the first usable address. Its schema is linked in [explicit-local-network.schema.json](../explicit-local-network.schema.json); the relational gateway rule is enforced by the implementation.

Legacy manifests omit the field on serialization, preserving the previous wire shape and normal default-network behavior. Unknown policy fields, versions, unaligned subnets, gateways and extra Compose IPAM/driver/external options refuse. An older CLI's deny-unknown-fields manifest decoder refuses the extension. Deployment must additionally require the exact read-only `--local-network-capabilities` response before admitting this profile; it cannot fall back to the old mode. The new supported CLI exposes `--choose-explicit-local-network` before constructing a LifecycleService, so selection does not create roots, recover jobs, reserve addresses or acquire executable permission.

Selection requires an explicitly pinned local DOCKER_HOST and no context/TLS selectors. It reuses the restoration allocator's 4096 candidates and bounded engine IPAM inventory plus actual host IPv4 routes, including VPN routes. This is a point observation rather than a reservation. The local Docker daemon/proxy is trusted. Docker Desktop host routes do not prove a complete remote VM route table; other remote TCP/SSH engines are refused. If any broader host route blocks the policy range, selection refuses instead of weakening that exclusion.

Install, Start and Restart repeat overlap admission under the existing operation lock, with no second journal. After Compose mutation they reobserve the actual network before reporting success. A preexisting default network is excluded from occupied ranges only after exact project/bundle/schema labels, full network ID, local bridge/no-options policy, IPv4 subnet/gateway and no IPv6/range override checks. Every other network remains an exclusion. On Linux, only the exact canonical subnet's main-table kernel/unicast/link route and exact gateway/local/host plus network/broadcast/link endpoint /32 routes in table local on `br-<validated owned ID prefix>` are exempted; matching VPN, static, different-interface and broader routes still refuse. A conflicting external race is a failed operation, not an automatic retry or cleanup.

Explicit-policy restoration requires a newly allocated subnet and rebinds the new manifest/Compose/gateway/hash; it never carries the old subnet into a new installation. Legacy restoration bytes remain unchanged. Stop preserves the existing owned-resource path and does not require free allocation capacity.
