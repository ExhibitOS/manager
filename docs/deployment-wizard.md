# Deployment preparation wizard

Manager's **배포 준비** panel offers beginner, intermediate and advanced guidance for local, existing Linux server and AWS reference preparation. It generates reviewed downloadable JSON, without invoking a shell, resolving credentials, connecting to a server, changing DNS or authorizing cloud charges. Changing an input invalidates the prepared download; validation errors omit input values.

Local and server output is public **OED 1.0.0-draft.1**, narrowed to the existing deployment adapters: digest-pinned nonzero runtime image, HTTP13200, one replica, PostgreSQL `database:5432/exhibitos`, and `data/assets`. An operator must supply the verified image reference; synthetic all-zero examples and tags are refused. Local preparation uses an environment locator. Server preparation additionally requires a non-root SSH user, bounded host/port and a separate SSH key locator. Environment locators contain variable names only; OS keychain locators contain service/account names only. The existing Generic SSH adapter resolves keychain on macOS; elsewhere use environment references. This panel neither creates nor verifies the credential entry. Never enter password, key or token contents.

Save and review the descriptor in a private operator workspace. The existing deployment `GenericSshAdapter.plan` validates it again with an independently pinned `known_hosts` file and registered Linux package/runtime inputs. Plan/apply/status/backup/update/rollback remain the execution adapter's responsibility. The panel does not import the OED into the existing local installation adapter yet; use the established verified local package controls for local installation.

Cloud output is a **separate existing AWS provider configuration**, not an invented cloud OED target. It includes only the account/project/resource identifiers accepted by deployment `awsConfiguration`. OpenTofu1.12.0 and official AWS6.42.0 are the existing pins. Save the configuration and use deployment `node bin/provider.mjs dry-run /absolute/private/config.json`. The preparation summary has unknown monthly cost, unenforced estimates, initial new-spend allowance **0 KRW**, and no runtime-health claim. Credentials are supplied externally as temporary environment/credential-provider entries. Actual apply/destroy remain refused without an observed isolated, authorized, zero-new-cost enforcement bound to the exact saved plan. If this cannot be established, choose **보유 서버로 직접 배포 준비** for Generic SSH; switching discards the cloud prepared download.

See the public deployment [Generic SSH instructions](https://github.com/ExhibitOS/deployment/blob/main/docs/generic-ssh.md) and [provider boundaries](https://github.com/ExhibitOS/deployment/blob/main/docs/providers.md). Before exposing a server, separately verify its domain/DNS/TLS/firewall and actual readiness. Before update or destruction, independently restore the original full backup. Preserve failed jobs and data; uncertain network responses never mean completion. The wizard itself has no remote jobs/status/logs or DNS integration yet, and no retry operation is dispatched here.

Verification separates bounded OED/provider builder regressions and read-only cross-repository consumer validation from native GUI, credentials, network/provisioning or update/rollback tests. The latter are not run by this preparation component. Original T10-04 remains incomplete: actual server→public domain→backup→update flow, remote job UI, token expiry, partial apply, network resume and incompatible DB recovery still require integration and actual qualification; predecessor T08-02/T10-03 gaps remain.
