# 관리 공간 선택과 새 복원 공간

일반 macOS 개발 앱의 **관리 공간 선택**에서 새 공간을 만들거나 등록된 이전 공간으로 돌아간다. 새 공간은 OS app-data 아래 `installations/<UUID>`에 자동 생성된다. 첫 기존 공간은 `local-runtime`이다. 임의 폴더 경로는 입력하지 않는다.

1. 기존 서버가 자동 정지되지 않고 기존 데이터가 보존되는 것을 확인한다. 필요하면 기존 공간에서 먼저 정지한다.
2. 확인 체크 후 **새 복원 공간 만들고 선택**을 누른다. 이는 빈 관리 폴더 생성과 선택 저장이며 DB 복원 완료가 아니다.
3. 상태를 다시 확인한 뒤 **백업 복원**에서 외부 키·암호화 사본·고정 유지보수 이미지·새 포트를 준비하고 복원을 실행한다.
4. 이전 공간으로 돌아가려면 목록에서 선택하고 확인 체크 후 **선택한 공간 사용**을 누른다. 서버·volume·키·사본을 자동 삭제하거나 이동하지 않는다.

실행 중인 앱 요청 동안 공간을 바꾸지 못한다. 모든 로컬 IPC 요청은 선택 토큰에 묶이며 이전 토큰은 전환 후 거부한다. A→B→A에서도 토큰을 새로 생성한다. 전환 후 이전 화면의 키 경로 입력·작업 기록·응답은 버리고 선택한 공간의 실제 상태를 다시 읽는다. 복원·백업 기록은 각 공간의 원본 폴더에 남는다.

앱을 다시 열면 마지막 저장한 선택을 사용한다. 이미 열린 다른 앱 창은 자기 공간을 유지하며 다음 실행만 마지막 선택을 따른다. 현재 폴더가 사라졌거나 읽히지 않아도 목록이 유효하면 원본을 재생성하지 않고 새 공간을 만들 수 있다. 목록 자체가 손상되었으면 자동 덮어쓰기를 하지 않는다.

`EXHIBITOS_MANAGER_ROOT`를 지정한 개발 실행은 고정 공간으로 전환을 비활성화한다. Windows의 공간 선택은 플랫폼 검증 전까지 비활성화한다. macOS 실제 GUI 조작, Windows·Podman, 전원 중단 복구는 별도 검증이며 빌드·합성 브라우저 검사로 대신하지 않는다.

## 선택 기록 보존과 복구

선택 목록은 OS app-data의 `installation-selection.json`(0600), 기존 목록 사본은 `selection-history/<시간>-<UUID>-<SHA256>.json`에 저장한다. 디렉터리는 0700이다. 이전 사본은 원자적 선택 교체 전에 동기화하며 자동 정리하지 않는다. Git 백업에 포함되지 않는 로컬 설정이다. 이는 선택 포인터 기록이며 DB·blob·설정·volume·암호화 키 백업을 대체하지 않는다.

목록 복구는 모든 Manager 앱과 해당 요청을 종료한 상태에서 한다. 현재 목록과 모든 공간 폴더를 별도 비공개 위치에 보존한다. 사본 파일명 SHA256과 실제 사본 해시를 비교하고 JSON 형식·등록된 공간·실제 폴더를 확인한다. 선택한 사본을 비공개 임시 파일로 복사해 0600으로 유지한 뒤 목록 파일을 원자적으로 교체하고 앱을 다시 연다. 등록된 폴더가 없어도 실제 데이터를 삭제하거나 임의로 재생성하지 않는다. 단위 검사는 이 메타데이터 복구와 기존·새 공간 보존을 검사한다. 전체 전원 장애 내구성은 아직 검증하지 않았다.

## 호환성

네이티브 앱과 프런트엔드는 함께 업데이트해야 한다. 기존 CLI·OED·Runtime 계약은 바꾸지 않는다. 개발 IPC 명령에는 `selectionToken`이 추가되므로 이전 프런트엔드는 새 backend에서 사용할 수 없다. 로컬 기본 창·허용된 원본과 생성된 명령 권한 경계는 유지한다.

## 일관된 외부 설정 사본

[앱 종료 상태의 암호화 설정 백업](profile-backup.md)을 사용해 현재 목록과 선택 이력·등록 공간 정보를 함께 보관할 수 있습니다. 단순 history 파일은 이 암호화 사본을 대신하지 않습니다. 새 버전 앱은 실행 내내 profile session 잠금을 보유하며 offline 백업·복원과 상호 배제됩니다. 전시 데이터와 키·환경 파일은 별도 runtime 백업 범위입니다.


### 독립적인 관리 공간 검사

개발 검사에서는 `EXHIBITOS_MANAGER_PROFILE`에 새 절대 경로를 지정하면 기존 사용자 관리 공간을 열지 않고 동일한 관리 공간 생성·선택 흐름을 검사할 수 있습니다. 경로를 미리 일반 폴더로 만들지 마세요. 앱이 보호된 새 폴더를 생성합니다. 고정 개발 실행 공간인 `EXHIBITOS_MANAGER_ROOT`와 동시에 지정하면 시작을 거부합니다. 검사가 끝나면 두 환경변수를 이전 값으로 돌려놓고, 생성된 후보·기록은 재열기 검사를 위해 보존합니다. 이 경로는 실제 설치 패키지나 서명·복원·전원 손실 검증을 대신하지 않습니다.
