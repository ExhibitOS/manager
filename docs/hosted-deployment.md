# 웹 전시 공개 — Pages와 선택적 Render

1차 hosted 경로는 승인한 정적 전시를 Cloudflare Pages에 올립니다. API 준비를 고르면 같은 정적 전시를 먼저 공개하고, 별도로 Render의 무료 API·PostgreSQL 자원을 준비합니다. 기존 서버 도구는 접힌 보조 영역에 보존하며 이 흐름의 필수 조건이 아닙니다.

Mac 앱에서 공개 방식 선택 → 제공자 API 토큰을 암호 입력란으로 입력 → 키체인 보관·계정 접근 확인 → 계정/워크스페이스와 선택적 API·DB 목록 선택 → 승인한 전시 묶음 선택 → 공개 동의 → 배포 순서입니다. 계정·서비스 식별자를 직접 입력하지 않습니다. 전시 제목·공개 식별자·프로젝트 이름은 native가 공개 묶음에서 확인합니다. 원본 촬영이나 임의 폴더는 배포 입력으로 받지 않습니다. 전체 파일·해시는 동봉된 배포 어댑터가 네트워크 업로드 전에 확인합니다.

토큰은 macOS Security.framework의 Keychain에 제공자별로 보관합니다. renderer의 password 값은 제출 직후 지우고, 명령행·환경변수·로그·브라우저 저장소에 쓰지 않습니다. 동봉 Node에는 native가 stdin으로만 전달하며 고정된 공개 결과만 반환합니다. 공식 가입·토큰 설정 링크와 실제 제공자 결과로 확인한 공개 URL만 OS 브라우저로 엽니다. 연결 해제는 해당 토큰만 제거하고 기존 전시·서비스·데이터·복구용 런타임 설정을 삭제하지 않습니다.

선택적 새 API의 tenant/owner bootstrap·서명 키는 native에서 생성하고 workspace/project별 Keychain에 보존합니다. 이는 새 빈 원격 DB 준비이며 로컬 Studio/CMS의 계정·작품 이전 완료를 의미하지 않습니다. 공개 publication ID·revision·index 해시는 선택한 공개 묶음 그대로 전달합니다. Render가 제공한 `expiresAt`만 표시하고 임의 만료일을 만들지 않습니다. 제공자의 `deployed`, API 응답 건강, 선택 전시의 기능 검증은 서로 구분합니다. 공개 호스트에서 실제 정적·API·데이터·복구가 확인되기 전 동적 전시 전체 성공으로 표시하지 않습니다.

쓰기 전에 secret-free target/source manifest pin과 작업 intent를 같은 native Keychain의 별도 작업 기록에 보존하고, 결과에는 양쪽 제공자의 안전한 ID·상태·URL만 기록합니다. 앱 재시작은 자동 POST를 하지 않습니다. 이전 작업은 표시하고 사용자가 ‘이전 배포 상태 확인’을 누르면 기존 이름·content hash·ID로 GET-only 조정합니다. 원래 묶음이 없거나 달라지면 조회·기존 URL은 유지하면서 새 업로드만 막습니다. 불확실한 생성은 완료나 무변경으로 가정하지 않으며, 새 Render 생성 전에 실제 자원 목록을 확인합니다. 자동 삭제는 없습니다.

검증은 TypeScript·lint·native offline check, 합성 응답의 provider/URL/비밀 경계 단위 검사, 브라우저의 정적 공개·입력 지우기·재시작 GET-only 흐름으로 구분합니다. 실제 제공자 토큰·계정·자원 생성·공개 URL·서명 앱의 UI는 실행한 증거 없이 통과로 주장하지 않습니다. 개발용 브라우저의 native bridge 모사는 실제 Keychain이나 클라우드 배포 증거가 아닙니다.

디자인 적용: P1/P3/P5·PD1 — 필요한 제공자만 연결하고, 공개 제목과 다음 행동을 먼저 보이며 내부 식별자는 상세에 둡니다. 화면 모드는 기존 system/light/dark 설정과 semantic 색·간격을 그대로 사용합니다.

Cloudflare 토큰에는 사용자 Memberships Read와 선택한 계정의 Cloudflare Pages Edit를 허용합니다. 계정 조회가 비거나 목록 권한이 부족하면 공식 GET /memberships로 수락한 API 접근 가능 계정을 확인합니다. 계정이 표시되는 것만으로 Pages 쓰기 권한이 검증됐다고 표시하지 않습니다.

Pages 요청 거절은 고정 단계·HTTP 상태·숫자 제공자 코드만 확인 코드에 표시합니다. 원격 응답 메시지·헤더·계정 ID·경로·토큰은 표시하지 않습니다. 단계 진단을 위해 배포 쓰기를 자동 재시도하지 않으며, 저장된 이전 작업의 상태 조회는 GET-only입니다.

실패 runner는 stdout에 `{errorCode: 고정코드}` 단일 프레임을 반환합니다. native는 알 수 없는 필드·중복 필드·미허용 코드를 거부하고 stderr 경고와 분리합니다. 이전 고정 stderr 코드만 반환하는 runner도 호환합니다. 미분류 JS 예외는 고정 처리 단계와 Error/TypeError 등 종류만 표시하며 원문 message/code/stack은 표시하지 않습니다. 2xx 응답의 예기치 않은 빈·거절 결과도 HTTP 상태를 보존합니다. 정상 성공 결과 wire와 네트워크·5xx 쓰기 불확실성 정책은 유지합니다.

Native의 stdin 전달·프로세스 대기·180초 제한·출력 상한 실패는 각각 고정 UNCERTAIN 코드로 구분합니다. 기존 180초·stdout256KiB·stderr4KiB 및 종료 정책은 유지하며, 상한 내의 stderr 경고만 유효한 stdout 오류 프레임과 분리합니다. 상한 초과는 성공이나 안전한 미실행으로 취급하지 않습니다.

Render 비용 동의 앞에는 무료 PostgreSQL의 생성30일 후 만료·접근 중단, 14일 유예 뒤 삭제, 제공자 백업 미지원, 별도 로컬 보관 필요와 앱의 자동 연장·재생성·유료 전환 없음이 표시됩니다. 이는 일반 무료 정책이며 실제 날짜는 여전히 제공자 `expiresAt`가 있을 때만 표시합니다. [Render 공식 무료 정책](https://render.com/docs/free)을 근거로 하며 자동 원격 백업 완료를 주장하지 않습니다. 같은 전시의 실제 응답을 받으면 UI의 이전 작업 receipt/phase도 함께 갱신하며 이를 위한 추가 Keychain 조회는 하지 않습니다.


### DB 백업과 전시 파일 사본

서버 백업을 만들 때, 이 Mac에 원래 공개 전시 파일이 남아 있고 원래 서버 설정과 일치하면 전시 파일의 별도 사본도 보관합니다. 기록에는 DB 백업 결과와 전시 파일 사본 보관 여부를 따로 표시합니다. 원래 폴더를 찾지 못하거나 사본 준비에 실패해도 완료된 DB 백업은 유지됩니다.

전시 파일 사본은 이 Mac의 해당 백업 작업 옆에 보관되며, 암호화 DB 백업 파일 자체에는 포함되지 않습니다. ‘암호화 백업 사본 보관’이 성공하면 선택한 위치 옆에 원래 작업에 연결된 별도 전시 사본도 준비합니다. 화면은 DB 백업 전달과 전시 사본 전달의 결과를 따로 표시합니다. 전시 사본 전달이 실패해도 이미 전달한 암호화 DB 백업은 유지합니다.

전달된 `ExhibitOS-publication-…` 폴더의 `publication` 하위 폴더는 기존 승인 전시 묶음 선택으로 다시 열 수 있습니다. 이는 공개용 파일이며 Studio 편집 원본이나 전체 복원 패키지가 아닙니다. 보관 기록은 생성 당시 검사 결과이며 현재 파일 전체를 다시 검사했다는 뜻은 아닙니다. 원래 작업 기록·키체인 설정이 없는 새 Mac에서의 전체 DB·서비스·설치 복원은 아직 미완료입니다.


### 백업의 원래 공개 서명 정보

새 서버 백업은 백업 때 확인한 공개 서명 정보만 기존 암호화 항목으로 보관합니다. 서명 개인키·관리자 암호·제공자 토큰을 추가로 백업하지 않습니다. ‘사본 복원 확인’은 먼저 백업을 인증하고, 저장한 공개 정보가 원래 기대값과 다르면 DB 검사를 시작하지 않습니다. 로컬 설정이 실제로 없는 경우에만 인증된 백업의 공개 정보를 사용하며, 접근 거부·잠금·손상된 설정은 그대로 오류로 처리합니다. 옛 백업에 이 정보가 없으면 원래 Mac의 신뢰 기록이 필요합니다.

기존 서버 백업 작업의 ‘사본 복원 확인’은 원래 백업 작업 기록과 키가 남아 있는 격리 DB 검사입니다. 새 Mac의 작업 기록 가져오기나 원래 비밀 설정·전체 서비스 복원이 완료된 것은 아닙니다. 일반 사용자 파일 선택·키체인 동작 검증은 별도로 남아 있습니다.


### 인증한 외부 사본의 원본 연결 기록

새 백업 사본 검증은 인증한 백업 식별자와 파일 목록을 선택한 사본에 연결하는 내부 기록도 보관합니다. 원본이 바뀌거나 이동하면 이 기록을 그대로 처리 입력으로 사용하지 않습니다. 키 내용은 이 기록에 저장하지 않으며 기존 검증 결과의 공개 형식은 유지합니다. 과거 검증 결과에 원본 연결 기록을 임의로 만들어 붙이지 않습니다.

연결 기록은 원본 식별용이며 복원 성공 증거가 아닙니다. 아래 격리 DB 검사는 이 기록으로 원본을 선택한 뒤 암호 인증을 다시 수행합니다. 전체 서비스 복원은 별도입니다.


### 외부에 보관한 사본의 격리 DB 검사

‘백업 사본 검증’에서 인증한 사본은 원래 배포 작업 기록이 없는 Mac에서도 별도의 빈 DB에 복원해 확인할 수 있습니다. 인증 기록에서 사본을 선택하고 별도로 보관한 원래 키 파일을 지정한 뒤 ‘새 격리 DB 검사’를 누릅니다. 현재 Manager에 포함된 복구 도구와 사본을 인증한 도구가 다르면 같은 폴더와 키로 먼저 사본 검증을 다시 실행합니다.

검사는 원본과 기존 결과를 보존하고 네트워크가 차단된 별도 작업 공간을 사용합니다. 실행 중에는 기존 백업·복원 취소를 사용할 수 있습니다. 실패·중단 후에는 ‘남은 검사 도구 상태 확인’으로 실제 도구 상태를 확인한 다음 새 후보로 다시 검사합니다. 앱을 닫았다고 도구가 취소됐다고 표시하지 않으며, 다시 열면 보존된 기록에서 상태를 확인합니다. 설치 전의 인증·검사 기록도 설치 후에 유지됩니다.

‘격리 DB 검사 완료’는 전시 서버 시작·전체 복원 완료를 뜻하지 않습니다. 원래 비밀 설정·서비스 실행 파일·공개 파일의 전체 복원과 실제 사용자 GUI 검증은 별도로 남아 있습니다. 이 경로에 원래 배포의 완료 작업을 임의로 생성하지 않습니다.


### 기존 Render 백업 대상 다시 연결

이전 공개 작업에 Render 기록이 없으면, API 방식에서 기존 API·데이터베이스를 선택하고 ‘원래 배포 프로젝트 이름’을 입력해 ‘기존 백업 대상 연결’을 사용할 수 있습니다. 이 Mac의 해당 프로젝트 설정이 이미 있어야 하며 새 설정·계정·키를 만들지 않습니다. 제공자의 서버·DB 상세, DB 연결 정보, 서버 환경변수를 읽어 기존 설정과 대상 관계를 검증하고 별도 연결 기록만 저장합니다. 배포·서비스 중지·접근 범위 변경·DB 연결은 수행하지 않습니다.

기존 정적 전시 작업은 보존하며 현재 선택한 전시 파일을 연결 대상의 원래 파일이라고 간주하지 않습니다. 이 연결로 시작하는 백업에는 전시 파일 사본이 자동 결합되지 않습니다. 손상된 연결 기록이나 누락·불일치 설정에서는 이전 대상에 자동으로 되돌아가지 않습니다. 실제 백업은 대상 재검증·writer 정지·좁은 접근 범위·백업 키 등 기존 조건을 별도로 충족해야 합니다. 현재 구현의 단위·합성 GUI 검사와 실제 계정에서의 연결 검증은 구분합니다.

백업 생성의 ‘백업 디스크 예산 · 고급 설정’에서는 총 추가 디스크 예산을 1 이상 정수 GiB로 제한할 수 있습니다. 이 상한은 Docker 작업 공간·인증 사본과 저장할 암호화 사본의 계획에 함께 사용합니다. 비워 두면 기존 자동 예산을 유지합니다. 예산 입력은 실제 여유 공간을 확인하거나 예약하지 않습니다. Docker VM 내부, Docker 디스크를 보관하는 Mac 파일시스템과 사본 저장 파일시스템의 여유를 각각 확인해야 합니다. 기존 6GiB 여유 기준, 원본 인증·writer 중지·좁은 IP 접근 조건은 그대로 적용됩니다. 관리 공간이나 백업 원본이 바뀌면 입력한 예산을 초기화합니다.
