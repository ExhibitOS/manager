# Unix fence lifetime

Trust Store holds both the immutable trust journal lock and an external profile anchor. A borrowed profile anchor must continue fencing the profile until its last in-process owner is dropped. Independent live owners still reject competing Store opens with TrustBusy.

On Unix, closing one descriptor can leave flock held by an unrelated fork's inherited descriptor until that child execs or exits. Close-on-exec does not eliminate the pre-exec interval. A deterministic native regression forks a child that waits using only async-signal-safe libc calls, drops the parent Store, attempts reopening while the child is alive, then releases and reaps the child before checking the result. On the previous source this test fails; final-owner explicit unlock makes it pass.

Unix anchors now share a single Arc-owned lock holder rather than duplicating file descriptors. The final owner explicitly unlocks before closing. Store explicitly releases its independent trust lock when its lifetime ends. Unix operation guards and the legacy profile-session guard also explicitly release their locks, so helper processes cannot extend a finished operation or session. Windows operation handle behavior remains unchanged. The borrow regression checks that dropping Store and then one borrowed anchor cannot release the profile while another borrower still owns it.

This fixes a reproduced lock-lifetime defect. The earlier default-parallel TrustBusy at trust_update.rs:462 did not identify the particular competing child, so its exact cause remains unproven. Passing subsequent parallel tests does not establish that attribution or prove host power-loss durability. No lock retries, timeout relaxation, repair of existing records, or permission/platform-gate weakening is introduced. Windows native anchor ownership and its support gates remain unchanged. Actual Windows full-core execution at 88a65c2 passed 89 tests with 4 explicitly ignored Docker integration cases; successful host checkpoint and GUI lifecycle remain unqualified.
